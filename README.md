# Concurrent Web Crawler (Search Spider Engine)

Многопоточный поисковый робот (краулер) на Go для рекурсивного обхода веб-сайтов, асинхронного парсинга HTML и динамического сбора данных в реальном времени.

## 🏗 Архитектура и Структура проекта

Проект спроектирован по принципам чистой архитектуры Go (модульность, инкапсуляция слоев и потокобезопасность):

```text
├── cmd/
│   └── server/
│       └── main.go         # Точка входа: оркестрация, инициализация и запуск каналов
├── internal/
│   ├── crawler/
│   │   └── worker.go       # Логика воркера (http-запросы с контекстом, парсинг goquery)
│   ├── models/
│   │   └── config.go       # Общие структуры данных (CrawlerConfig)
│   └── registry/
│       └── registry.go     # Потокобезопасный реестр уникальных URL (Mutex-инкапсуляция)
├── go.mod
└── go.sum
```

Стек технологий и Concurrency Patterns:
Worker Pool: Управление пулом параллельных горутин-воркеров для оптимизации сетевого I/O.

Data Pipelines: Асинхронный обмен данными через буферизированные направленные каналы (<-chan, chan<-).

In-Memory Registry: Потокобезопасный реестр на базе sync.Mutex с защитой от Race Condition и бесконечных циклов (дублирования URL). Внутреннее состояние скрыто, доступ предоставляется через потокобезопасное API пакета (Visit(), Count()).

Graceful Shutdown: Использование context.WithTimeout для безопасного завершения всех горутин и отмены зависших сетевых запросов.

Background Analytics: Сбор метрик без дрейфа времени с использованием time.Ticker.

🚀 Быстрый старт
1. Установка зависимостей
Bash
```
go mod tidy
```
2. Запуск краулера
Bash
```
go run cmd/server/main.go
```
Программа запустит 5 параллельных воркеров, начнет рекурсивный обход стартовых сайтов, каждые 2 секунды будет выводить аналитику в консоль и автоматически завершит работу через 10 секунд по таймауту контекста.

🧠 Ключевые инженерные решения в проекте:
Инкапсуляция конкурентного доступа: Мьютекс и базовая мапа полностью изолированы внутри пакета registry. Внешний код (main, crawler) не имеет прямого доступа к памяти, что исключает случайные Race Conditions.

Предотвращение утечек памяти: Реализовано обязательное и своевременное освобождение системных ресурсов (resp.Body.Close()) сразу после загрузки DOM дерева в goquery, а также корректная остановка таймеров через defer ticker.Stop().

Рекурсивный Pipeline без дедлоков: Потоки задач и результатов разделены. Менеджер в main читает результаты, валидирует новые ссылки и динамически подкидывает их в очередь воркерам прямо во время работы пула.
